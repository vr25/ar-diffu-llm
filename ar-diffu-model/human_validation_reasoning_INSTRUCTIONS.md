# Human Validation Instructions — Reasoning Task (LLM-Judge Agreement Check)

## Purpose
We used an LLM (Claude Sonnet 5) to judge correctness of model answers to 30 simple
reasoning questions (arithmetic, word problems, time/date logic, basic deduction),
generated by 3 diffusion models and 3 AR models across multiple sampling
temperatures. This is the **first human validation of the reasoning-task judge**
(the factual-QA judge was already validated separately). Two independent raters are
doing this so we can compute both human-vs-LLM agreement and human-vs-human
inter-annotator agreement (Cohen's kappa).

**Rate independently. Do not look at the LLM judge's verdict, and do not compare
notes with the other rater, until you have finished all 30 rows.**

## File
You have been given one of:
- `human_validation_reasoning_RATERA_thirdperson.csv`
- `human_validation_reasoning_RATERB_undergrad.csv`

Both contain the same 30 rows/questions. Columns:

| Column | Description |
|---|---|
| `idx` | Row index (0-29) |
| `diffu_model` | Which diffusion model generated the answer in this row |
| `temp` | Sampling temperature used |
| `question` | The reasoning question asked |
| `answer` | The model's raw generated answer (may show work, use LaTeX-style formulas, or be truncated/garbled) |
| `llm_judge_verdict` | **DO NOT LOOK AT THIS UNTIL YOU FINISH ALL 30 ROWS** — the LLM judge's verdict (correct/incorrect) |
| `llm_judge_reason` | **DO NOT LOOK AT THIS UNTIL YOU FINISH ALL 30 ROWS** — the LLM judge's stated reason |
| `human_verdict` | **YOU FILL THIS IN** — write `CORRECT` or `INCORRECT` |
| `human_notes` | **YOU FILL THIS IN** — optional one-line note, especially for disagreements or edge cases |

## How to label

For each row, read only `question` and `answer`. Ignore the `llm_judge_*` columns
until you are completely done with all 30 rows.

**Judging rule — does the answer arrive at the correct final answer?**
- These are simple problems — feel free to work out the correct answer yourself
  (e.g., do the arithmetic, count the days, follow the logic) before judging.
- Ignore formatting, verbosity, "showing work," step-by-step derivations, LaTeX-style
  formulas (`\frac{}{}`, etc.), or awkward phrasing. Only judge whether the **final
  stated answer** is correct.
- If the correct final answer appears anywhere in the response (even wrapped in a
  long derivation), mark **CORRECT**.
- If the response is **truncated before it states a final answer**, mark
  **INCORRECT** (even if the reasoning up to that point looks correct).
- If the response is nonsensical, refuses to answer, or **contradicts itself**
  (e.g., states two different final answers), mark **INCORRECT**.
- If the response states a final answer but it's the **wrong** one, mark
  **INCORRECT**.

## Process
1. Go row by row, top to bottom. Do not scroll ahead or peek at the last two
   columns.
2. Fill in `human_verdict` (CORRECT or INCORRECT) and an optional short
   `human_notes`.
3. Only after finishing all 30 rows, you may look at `llm_judge_verdict` /
   `llm_judge_reason` if you're curious how you compared — not required.
4. Save the file and return it. Please don't rename columns or reorder rows.

Estimated time: ~10-15 minutes.
